The following API endpoints are custom additions in AnglerPhish and are not available in the standard Gophish distribution.

Landing Pages MFA Extension

MFA simulation adds a second verification step to landing pages. After users submit credentials, they receive an SMS with a verification code and must enter it to proceed.

Additional Page Parameters (MFA):

The following parameters can be included when creating or updating a landing page:

Parameter Type Description
enable_mfabooleanEnable MFA simulation for this landing page
mfa_sms_profile_idintegerID of the SMS profile to use for sending verification codes
mfa_fromstringOverride sender ID for MFA SMS (optional, uses profile default if empty)
mfa_messagestringSMS message template. Use {{.Code}} for the code. Default: "Your verification code is: {{.Code}}"
mfa_code_lengthintegerLength of verification code (4, 6, or 8). Default: 6
mfa_code_typestringCode type: "numeric", "alpha", or "alphanumeric". Default: "numeric"
mfa_inject_pagebooleanIf true, shows built-in MFA verification page. If false, you handle MFA in your landing page HTML. Default: true
mfa_page_htmlstringCustom HTML for MFA verification page (only used if mfa_inject_page is true). If empty, uses default template.
POST /api/pages/

Creates a landing page with MFA enabled. [Show Example]

Request Body:
{
  "name": "MFA Login Page",
  "html": "<html>...</html>",
  "capture_credentials": true,
  "capture_passwords": true,
  "redirect_url": "https://example.com",
  "enable_mfa": true,
  "mfa_sms_profile_id": 1,
  "mfa_from": "MyBank",
  "mfa_message": "Your security code is: {{.Code}}",
  "mfa_code_length": 6,
  "mfa_code_type": "numeric",
  "mfa_inject_page": true
}

Response: 201 Created
{
  "id": 1,
  "name": "MFA Login Page",
  ...
}
GET /api/pages/mfa_template

Returns the default MFA verification page HTML template. Use this to customize the MFA page. [Show Example]

Response: 200 OK
{
  "success": true,
  "message": "Default MFA template",
  "data": "<!DOCTYPE html>\n<html>\n<head>...</head>\n<body>...</body>\n</html>"
}

Template Variables:
- {{if .Error}}...{{end}} - Shows error on failed verification
- Form must POST "mfa_code" field

MFA Events in Campaign Results:

When MFA is enabled, the following additional events are tracked:

  • MFA Code Sent - Code was generated and sent via SMS
  • MFA Code Verified - User entered correct verification code
  • MFA Code Failed - User entered incorrect code

Database Encryption

AnglerPhish supports AES-256-GCM encryption for sensitive database fields including SMTP passwords, SMS provider credentials, and IMAP passwords.

Note: Encryption is optional and backward compatible. The application works without an encryption key, and encrypted/plaintext data can coexist.

Environment Variable

Variable Description
ANGLERPHISH_ENCRYPTION_KEY32-byte encryption key for AES-256-GCM. If not set, encryption is disabled.

CLI Commands

--generate-encryption-key

Generates a new random 32-byte encryption key. [Show Example]

./anglerphish --generate-encryption-key

Output:
ANGLERPHISH_ENCRYPTION_KEY=xK9m2pL7qR4sT6vW8yB1cD3eF5gH7jK9
--migrate-encryption

Encrypts all existing plaintext sensitive fields in the database. [Show Example]

# Set the encryption key first
export ANGLERPHISH_ENCRYPTION_KEY=your-32-byte-key   # Linux/Mac
set ANGLERPHISH_ENCRYPTION_KEY=your-32-byte-key      # Windows CMD

# Run migration
./anglerphish --migrate-encryption

Output:
Migrating plaintext fields to encrypted...
SMTP passwords: 5 encrypted, 0 skipped
SMS provider configs: 3 encrypted, 0 skipped
IMAP passwords: 2 encrypted, 0 skipped
Migration complete!
--migrate-decryption

Decrypts all encrypted fields back to plaintext (reverse migration). [Show Example]

# Requires the encryption key
export ANGLERPHISH_ENCRYPTION_KEY=your-32-byte-key   # Linux/Mac
set ANGLERPHISH_ENCRYPTION_KEY=your-32-byte-key      # Windows CMD

# Run reverse migration
./anglerphish --migrate-decryption

Output:
Decrypting all encrypted fields...
SMTP passwords: 5 decrypted, 0 skipped
SMS provider configs: 3 decrypted, 0 skipped
IMAP passwords: 2 decrypted, 0 skipped
Decryption complete!
--dry-run

Preview migration changes without applying them. Use with --migrate-encryption or --migrate-decryption. [Show Example]

# Preview what would be encrypted (no changes made)
./anglerphish --migrate-encryption --dry-run

Output:
DRY RUN - Previewing encryption migration (no changes will be made)...
SMTP passwords: 5 would be encrypted, 0 would be skipped
SMS provider configs: 3 would be encrypted, 0 would be skipped
IMAP passwords: 0 would be encrypted, 2 would be skipped

Dry run complete. Use --migrate-encryption without --dry-run to apply changes.

# Preview what would be decrypted
./anglerphish --migrate-decryption --dry-run
--encryption-status

Shows the current encryption status of the database. [Show Example]

./anglerphish --encryption-status

Output:
Encryption Enabled: Yes
SMTP Passwords: 5 encrypted, 0 plaintext
SMS Provider Configs: 3 encrypted, 0 plaintext
IMAP Passwords: 2 encrypted, 0 plaintext

SMTP (Sending Profiles)passwordSMTP server password
SMS (SMS Profiles)provider_configTwilio/Vonage API credentials

Production Deployment

For systemd services, use an environment file with restricted permissions: [Show Example]

# Create secrets file
sudo mkdir -p /etc/anglerphish
echo "ANGLERPHISH_ENCRYPTION_KEY=your-32-byte-key" | sudo tee /etc/anglerphish/secrets.env
sudo chmod 600 /etc/anglerphish/secrets.env
sudo chown root:root /etc/anglerphish/secrets.env

# In systemd service file (/etc/systemd/system/anglerphish.service)
[Service]
EnvironmentFile=/etc/anglerphish/secrets.env
ExecStart=/opt/anglerphish/anglerphish
Important: Never lose your encryption key! If lost, encrypted passwords become unrecoverable and you'll need to re-enter all credentials.
